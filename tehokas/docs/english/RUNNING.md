# Running the project

This guide covers how to install, run, test, and deploy the Project
Checklist app. Unless noted otherwise, every command below runs inside the
`tehokas/` folder (the Laravel application root).

## Prerequisites

- **PHP 8.3 or higher** (the project was built and tested with PHP 8.5) and
  Composer.
- **Node 22 or higher** and npm.
- The `pdo_sqlite` PHP extension enabled — the default database is SQLite.
- Docker, only if you choose the Sail path instead of a local install.

## Local installation

1. Clone the repository and enter the application folder:

   ```bash
   git clone git@github.com:VitorInacioBorges/tehokas-code-challenge.git
   cd tehokas-code-challenge/tehokas
   ```

2. Run the setup script, which installs the PHP dependencies, creates `.env`
   from `.env.example`, generates the `APP_KEY`, runs the migrations, and
   builds the frontend assets:

   ```bash
   composer setup
   ```

3. Seed the demo data (see [Demo data](#demo-data)):

   ```bash
   php artisan db:seed
   ```

4. Start the development server (Laravel and Vite together, with
   hot-reload):

   ```bash
   composer run dev
   ```

   The application is then available at `http://localhost:8000`.

## Sail (Docker)

The repository already includes `tehokas/compose.yaml`, generated by Sail
(`php artisan sail:install --with=none`), with only the `laravel.test`
service — no extra services, since the project uses SQLite instead of a
client-server database.

1. Enter the application folder and copy `.env`:

   ```bash
   cd tehokas-code-challenge/tehokas
   cp .env.example .env
   ```

2. Install the PHP dependencies without needing PHP/Composer installed
   locally, using Sail's helper image (see the note below about the image
   version):

   ```bash
   docker run --rm -u "$(id -u):$(id -g)" -v "$(pwd):/var/www/html" -w /var/www/html laravelsail/php84-composer:latest composer install --ignore-platform-reqs
   ```

3. Bring the containers up and prepare the application:

   ```bash
   ./vendor/bin/sail up -d
   ./vendor/bin/sail artisan key:generate
   ./vendor/bin/sail artisan migrate --seed
   ./vendor/bin/sail npm install && ./vendor/bin/sail npm run build
   ```

**Note on the image in step 2:** at the time this document was written, Sail
does not yet publish a `laravelsail/php85-composer` image; the `php84-composer`
image (the most recent one available) is used only to install the PHP
dependencies without requiring PHP or Composer on the host machine. The
application container itself (`laravel.test`, defined in `compose.yaml`)
already runs PHP 8.5.

The Sail flow above was generated and reviewed, but it was **not validated on
a machine with Docker available** while this project was being prepared.

## Tests and `composer ci:check`

```bash
php artisan test --compact   # runs the Pest suite (compact format)
composer ci:check            # full quality gate
```

The suite has **87 tests (336 assertions)**. `composer ci:check` runs, in
this order: `vp check` (frontend lint and formatting), `tsc --noEmit`
(TypeScript type checking), and the Composer `test` script, which in turn
runs Pint (`lint:check`), PHPStan level 7 (`types:check`), and the Pest suite
(`php artisan test`). This is the command that decides whether a PR can be
merged — see why in [Practices](PRACTICES.md#code-quality).

## Deploying to Render

See the "Deploy (Render)" section in the root
[README](../../../README.md) for the full publishing walkthrough, what
happens on container boot, and the limitations of the free plan. In short:

1. In the Render dashboard, use **New > Blueprint** and connect the GitHub
   repository. Render reads `render.yaml` from the repository root.
2. `tehokas/Dockerfile` builds the production image (FrankenPHP + PHP 8.5),
   and `tehokas/docker/start.sh` is the entrypoint: it creates and seeds the
   SQLite database if the file does not exist yet, runs the migrations, and
   only then calls `php artisan optimize`.
3. The public URL is generated by Render at publish time and shows up in the
   service's dashboard — there is no way to know it in advance.

## Common problems

- **`php artisan wayfinder:generate` produced functions without `.form()`,
  and Inertia's `<Form>` breaks at build time.** The pages rely heavily on
  the `{...Controller.action.form()}` pattern (for example,
  `resources/js/pages/projects/show.tsx`). If you run the Wayfinder command
  manually instead of letting `npm run build`/`npm run dev` do it through the
  Vite plugin (`wayfinder({ formVariants: true })` in `vite.config.ts`),
  always include the `--with-form` flag:

  ```bash
  php artisan wayfinder:generate --with-form
  ```

- **`Illuminate\Foundation\ViteException: Unable to locate file in Vite
  manifest.`** The frontend assets have not been compiled yet (or
  `manifest.json` is stale). Run `npm run build` for a production build, or
  `npm run dev`/`composer run dev` for the development server with
  hot-reload.

- **The local SQLite database does not exist.** `composer setup` already
  takes care of this, but if `database/database.sqlite` is missing for any
  reason, create it manually before migrating:

  ```bash
  touch database/database.sqlite
  php artisan migrate
  ```
